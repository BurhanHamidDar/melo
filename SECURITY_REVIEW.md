# Melo V2 — Security Review & Vulnerability Assessment

**Date:** 15 November 2026  
**Auditor:** Antigravity Security & Systems Lead  
**Scope:** Original Android App, Network Calls, Backend, Admin Dashboard, Database, and Storage Architecture  

---

## 1. Resolved Security Findings

### 1.1 In-App Client Supabase Queries [RESOLVED]
- **Previous Vulnerability:** The upstream app contained direct PostgREST client code (`io.github.jan.supabase.postgrest.from`) in `AdminPanelScreen.kt` and `TodoActivity.kt`, allowing client-side inserts and queries to `app_updates`, `broadcast_notifications`, and `active_sessions`. Hardcoded publishable keys were embedded in source code.
- **Remediation Completed:**
  - `TodoActivity.kt` and `AdminPanelScreen.kt` permanently deleted.
  - `io.github.jan-tennert.supabase:postgrest-kt` dependency removed from `app/build.gradle.kts`.
  - All direct queries removed from `MainActivity.kt`.
  - In-app admin login and settings screens removed from `SettingsScreen.kt`, `LoginScreen.kt`, and `NavigationBuilder.kt`.
  - 0 remaining references to Supabase in the Android codebase.

### 1.2 In-App Admin Login Screen [RESOLVED]
- **Previous Vulnerability:** An admin authentication screen was exposed inside the public Android APK.
- **Remediation Completed:** The admin console is now a standalone web application built with Next.js 15 (`admin/`), communicating exclusively with the Go API using Firebase ID tokens and database-backed RBAC (`admin_roles`).

### 1.3 Unverified App Update Installation [RESOLVED]
- **Previous Vulnerability:** The legacy updater downloaded APKs without cryptographic hash verification prior to installation.
- **Remediation Completed:** In Melo V2, `/v1/app/update` returns the exact `sha256`, `signing_cert_sha256`, and `min_supported_version_code`. The Go backend validates releases before publishing, and the Android client validates SHA-256 before handing off to Android's `PackageInstaller`.

## 2. API Security Architecture (Go Backend)

- **Token Verification:** Every protected endpoint verifies the Firebase ID token's signature, issuer, and expiry via Firebase Admin SDK.
- **Identity Isolation:** Database queries strictly enforce `WHERE user_id = $1` using the verified internal user UUID derived from the Firebase UID. Never trust client-supplied user IDs.
- **Rate Limiting:** Protect public and authentication-adjacent endpoints with IP-based and token-based token-bucket rate limiters.
- **Input Validation:** Strict bounds on usernames, playlist titles, and pagination page sizes. SQL parameterization prevents injection.
- **CORS:** Restricted to the authorized admin dashboard domain (`ALLOWED_ADMIN_ORIGINS`).

---

## 3. Storage Security (Cloudflare R2)

- **Presigned URLs:** Clients upload directly to R2 using short-lived (5-minute) presigned PUT URLs generated by the backend.
- **Access Control:** Secret access keys never leave the Go API server.
- **Validation:** On `/v1/uploads/complete`, the server inspects the object in R2 to confirm content length and MIME type before activating the asset record.

---

## 4. Privacy & Compliance

- **Guest by Default:** No listener is forced to register to stream audio or use local playback.
- **Data Minimization:** No collection of contacts, geolocation, or real identities. Listening history sync is strictly opt-in.
- **Account Deletion:** Full deletion and anonymization workflow provided via `/v1/me/account-deletion`.
- **GPL-3.0 License:** All upstream attribution and copyright notices are preserved across all modules.
